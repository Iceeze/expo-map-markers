# Карта и изображения

Учебное мобильное приложение на React Native, Expo и TypeScript. Пользователь добавляет и удаляет маркеры на карте, просматривает их координаты и прикрепляет фотографии из галереи. Маркеры и фотографии доступны после перезапуска приложения.

## Установка и запуск

1. Установите актуальную **LTS-версию Node.js** с [официального сайта](https://nodejs.org/en/download).
2. Установите **Expo Go** на телефон Android или iPhone. Ссылки на приложение есть на [странице настройки Expo](https://docs.expo.dev/get-started/set-up-your-environment/). Версия Expo Go должна поддерживать вашу установленную версию SDK (в текущем проекте это SDK 58).
3. Откройте терминал в папке проекта и введите команды:

   ```powershell
   npm ci
   npm start
   ```

   `npm ci` устанавливает зависимости из `package-lock.json`, а `npm start` запускает сервер разработки и показывает QR-код.

Оставляйте терминал с сервером открытым во время работы. Для остановки нажмите `Ctrl+C`.

## Как устроен проект

| Файл | Назначение |
| --- | --- |
| `app/index.tsx` | Главный экран с картой и переходом к выбранному маркеру. |
| `app/marker/[id].tsx` | Показывает координаты и фотографии выбранного маркера. Здесь можно добавить и удалить фото или удалить сам маркер. |
| `app/_layout.tsx` | Подключает провайдер базы данных и настраивает навигацию. |
| `app/+not-found.tsx` | Показывает сообщение, если открыт неизвестный адрес экрана. |
| `components/Map.tsx` | Отображает карту и маркеры, обрабатывает долгое нажатие и состояние загрузки. |
| `components/MapErrorBoundary.tsx` | Показывает запасной экран при ошибке отрисовки карты в React. |
| `components/ImageList.tsx` | Показывает список фотографий и кнопки удаления. |
| `contexts/DatabaseContext.tsx` | Управляет соединением SQLite, очередью операций, списком маркеров, состояниями загрузки и ошибок. |
| `database/schema.ts`, `database/migrations/` | Настраивают SQLite и последовательно применяют миграции. |
| `database/operations.ts` | Содержит запросы к базе и связывает записи с файлами фотографий. |
| `database/photos.ts` | Копирует выбранные фотографии в папку приложения, восстанавливает их URI и удаляет локальные копии. |
| `types.ts` | Описывает форму координат, маркера, фотографии и параметров перехода. |
| `app.json` | Настройки Expo: название приложения, платформы и подключённые плагины. |
| `package.json` | Зависимости и команды запуска проекта. |
| `tsconfig.json` | Настройки проверки TypeScript. |

Оба экрана получают данные и операции через `useDatabase()`. Провайдер загружает список маркеров при запуске и обновляет его после успешной записи. Экран деталей запрашивает фотографии только выбранного маркера. Доступ к SQLite идёт через `expo-sqlite`, который поставляется со своими типами TypeScript. Указанный в задании `@types/sqlite3` зафиксирован на `3.1.11`, чтобы установка не подтягивала нативный драйвер SQLite для Node.js.

Для карты используется `react-native-maps`, для галереи — `expo-image-picker`, для переходов между файлами экранов — `expo-router`.

## Схема базы данных

SQLite хранит данные в `markers.db`.

| Таблица | Поля |
| --- | --- |
| `markers` | `id INTEGER PRIMARY KEY AUTOINCREMENT`, `latitude REAL NOT NULL`, `longitude REAL NOT NULL`, `created_at DATETIME DEFAULT CURRENT_TIMESTAMP` |
| `marker_images` | `id INTEGER PRIMARY KEY AUTOINCREMENT`, `marker_id INTEGER NOT NULL`, `uri TEXT NOT NULL`, `created_at DATETIME DEFAULT CURRENT_TIMESTAMP` |

Одному маркеру соответствует несколько фотографий. Внешний ключ `marker_images.marker_id` ссылается на `markers.id`. При открытии соединения включается `PRAGMA foreign_keys = ON`, поэтому `ON DELETE CASCADE` удаляет связанные записи вместе с маркером.

При добавлении фото приложение копирует файл в `Paths.document/marker-photos` и сохраняет в `uri` путь относительно каталога документов. При чтении из него получается локальный URI для отображения. Удаление записи очищает копию приложения. Оригинал в галерее остаётся доступен.

## Миграции базы данных

- `0 → 1` создаёт таблицы `markers` и `marker_images`.
- `1 → 2` добавляет индекс `idx_marker_images_marker_id` для выборки фотографий по `marker_id` и каскадного удаления. Существующие строки сохраняются.

При открытии приложение читает `PRAGMA user_version` и выполняет только отсутствующие шаги. Изменения схемы и номера версии записываются в одной транзакции. При ошибке SQLite откатывает оба изменения, поэтому после устранения причины можно повторить инициализацию.

Для демонстрации на чистой базе временно оставьте в `database/schema.ts` только `initialSchema` в списке `migrations` и уберите импорт `imageIndex`. Создайте маркер с фотографией, верните второй шаг в код и перезапустите тот же проект на том же устройстве. В инспекторе SQLite запрос `PRAGMA user_version;` вернёт `2`, а `PRAGMA index_list('marker_images');` покажет новый индекс. Маркер и фотографию можно открыть на карте.

## Ошибки и ограничения

- При ошибке открытия или подготовки базы приложение показывает сообщение с кнопкой **«Повторить»**. Провайдер закрывает соединение после неудачной инициализации и при размонтировании, дождавшись операций в очереди.
- При сбое записи интерфейс сохраняет прежние данные и показывает сообщение об ошибке. Загрузку фотографий можно повторить отдельно. Для нарушений ограничений и временной блокировки SQLite предусмотрены отдельные сообщения.
- Удаление маркера выполняется в транзакции. Локальные копии файлов удаляются после её фиксации. Если запись нового фото не удалась, приложение очищает созданную копию. При следующем открытии базы оно повторяет очистку файлов, на которые больше нет ссылок.
- В режиме разработки операции и причины сбоев выводятся в консоль с префиксом `[SQLite]`.
- Приложение рассчитано на **Android и iOS через Expo Go**. Веб-версия не предусмотрена.
- Карта загружает изображения местности из сети. Без интернета часть карты может оставаться пустой, уже загруженные участки иногда доступны из кеша устройства.
- Если карта не сообщает о готовности за 20 секунд, появляется сообщение с кнопкой **«Повторить»**. На Android таймер ожидает событие `onMapLoaded`, на iOS — инициализацию нативного компонента через `onMapReady`.
- `MapErrorBoundary` перехватывает ошибки отрисовки React. Он не может перехватить все сетевые ошибки карт или сбой самого нативного приложения. У библиотеки карт нет универсального события для каждой ошибки загрузки участков, поэтому таймер — простая подсказка при долгом ожидании, а не точная диагностика сети.
- Ошибки открытия галереи и получения изображения показываются сообщением. Если выбранная фотография стала недоступной, в списке появляется пояснение.
- Неверный или отсутствующий `id` маркера открывает экран **«Маркер не найден»** с возвратом к карте.

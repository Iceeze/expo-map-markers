# Карта и изображения

Учебное мобильное приложение на React Native, Expo SDK 58 и TypeScript. Пользователь добавляет и удаляет маркеры на карте, просматривает их координаты и прикрепляет фотографии из галереи. Маркеры и фотографии доступны после перезапуска приложения. Карта показывает текущее местоположение, а при приближении к сохранённому маркеру приложение отправляет локальное уведомление.

## Установка и запуск

1. Установите актуальную **LTS-версию Node.js** с [официального сайта](https://nodejs.org/en/download).
2. Установите **Expo Go** на телефон Android или iPhone. Ссылки на приложение есть на [странице настройки Expo](https://docs.expo.dev/get-started/set-up-your-environment/). Версия Expo Go должна поддерживать вашу установленную версию SDK (в текущем проекте это SDK 58).
3. Откройте терминал в папке проекта и введите команды:

   ```powershell
   npm ci
   npm start
   ```

   `npm ci` устанавливает зависимости из `package-lock.json`, а `npm start` запускает сервер разработки и показывает QR-код.

Оставляйте терминал с сервером открытым во время работы. Для остановки нажмите `Ctrl+C`.

На iPhone откройте QR-код камерой, когда телефон и компьютер подключены к одной сети. На macOS можно запустить Expo Go в iOS Simulator командой `npm run ios`. Для собственной нативной сборки используйте `npx expo run:ios` на macOS с версией Xcode, поддерживаемой SDK 58. При первом запуске разрешите доступ к местоположению и уведомлениям. [Требования Expo SDK 58](https://docs.expo.dev/versions/v58.0.0/)

## Как устроен проект

| Файл | Назначение |
| --- | --- |
| `app/index.tsx` | Главный экран с картой и переходом к выбранному маркеру. |
| `app/marker/[id].tsx` | Показывает координаты и фотографии выбранного маркера. Здесь можно добавить и удалить фото или удалить сам маркер. |
| `app/_layout.tsx` | Подключает провайдер базы данных и настраивает навигацию. |
| `app/+not-found.tsx` | Показывает сообщение, если открыт неизвестный адрес экрана. |
| `components/Map.tsx` | Отображает карту, сохранённые маркеры и текущую позицию, обрабатывает долгое нажатие и состояние загрузки. |
| `components/MapErrorBoundary.tsx` | Показывает запасной экран при ошибке отрисовки карты в React. |
| `components/ImageList.tsx` | Показывает список фотографий и кнопки удаления. |
| `contexts/DatabaseContext.tsx` | Управляет соединением SQLite, очередью операций, списком маркеров, состояниями загрузки и ошибок. |
| `database/schema.ts`, `database/migrations/` | Описывают таблицы для Drizzle, настраивают SQLite и применяют миграции. |
| `database/operations.ts` | Выполняет запросы через Drizzle ORM и связывает записи с файлами фотографий. |
| `database/photos.ts` | Копирует выбранные фотографии в папку приложения, восстанавливает их URI и удаляет локальные копии. |
| `types.ts` | Описывает координаты, маркеры и фотографии. |
| `contexts/LocationContext.tsx` | Управляет GPS-подпиской и разрешениями. |
| `services/proximity.ts` | Вычисляет расстояние и последовательно обрабатывает вход в зоны маркеров и выход из них. |
| `services/notifications.ts` | Показывает, отменяет и убирает локальные уведомления. |
| `app.json` | Настройки Expo: название приложения, платформы и подключённые плагины. |
| `package.json` | Зависимости и команды запуска проекта. |
| `tsconfig.json` | Настройки проверки TypeScript. |

Оба экрана получают данные и операции через `useDatabase()`. Провайдер загружает список маркеров при запуске и обновляет его после успешной записи. Экран деталей запрашивает фотографии только выбранного маркера.

Drizzle ORM подключается к открытому соединению `expo-sqlite` и использует описания таблиц из `database/schema.ts` для типизации запросов. Через Drizzle приложение читает, добавляет и удаляет маркеры и фотографии.

Для карты используется `react-native-maps`, для галереи — `expo-image-picker`, для переходов между файлами экранов — `expo-router`.

## Схема базы данных

SQLite хранит данные в `markers.db`.

```sql
CREATE TABLE markers (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    latitude REAL NOT NULL,
    longitude REAL NOT NULL,
    created_at DATETIME DEFAULT CURRENT_TIMESTAMP
);

CREATE TABLE marker_images (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    marker_id INTEGER NOT NULL,
    uri TEXT NOT NULL,
    created_at DATETIME DEFAULT CURRENT_TIMESTAMP,
    FOREIGN KEY (marker_id) REFERENCES markers (id) ON DELETE CASCADE
);
```

Одному маркеру соответствует несколько фотографий. Внешний ключ `marker_images.marker_id` ссылается на `markers.id`. При открытии соединения включается `PRAGMA foreign_keys = ON`, поэтому `ON DELETE CASCADE` удаляет связанные записи вместе с маркером.

При добавлении фото приложение копирует файл в `Paths.document/marker-photos` и сохраняет в `uri` путь относительно каталога документов. При чтении из него получается локальный URI для отображения. Удаление записи очищает копию приложения. Оригинал в галерее остаётся доступен.

## Миграции базы данных

При открытии приложение читает `PRAGMA user_version` и выполняет только отсутствующие шаги. Изменения схемы и номера версии записываются в одной транзакции. При ошибке SQLite откатывает оба изменения, поэтому после устранения причины можно повторить инициализацию.

## Геолокация и локальные уведомления

Синий маркер **«Вы здесь»** обновляется по данным `expo-location`. Кнопка **«Моё местоположение»** центрирует карту на нём. Подписка находится над навигацией и продолжает работать на экране фотографий, пока приложение активно. При уходе в фон подписка закрывается, а после возврата приложение проверяет разрешения и ждёт новых координат. При ошибке на карте появляется сообщение с кнопкой **«Повторить»**.

Приложение вычисляет расстояние по формуле Хаверсина и проверяет радиус **100 м** вокруг каждой сохранённой метки. Оно хранит идентификаторы активных уведомлений в памяти и обрабатывает обновления последовательно. Для каждой метки приходит одно уведомление за визит. При выходе из зоны или удалении метки приложение отменяет запланированное уведомление, убирает доставленное из Центра уведомлений и освобождает запись в памяти. Это позволяет отправить новое уведомление при следующем визите.

При сворачивании приложения список активных уведомлений хранится в памяти. После полного перезапуска начинается новая сессия. Приложение убирает старые уведомления о метках и после получения координат снова проверяет зоны.

## Как проверить задание 3 на iOS

Команды `npm run typecheck` и `npm test` проверяют типы, расчёт расстояния, повторный вход, несколько меток, удаление и сбои уведомлений. Для автоматических тестов нужна Node.js версии 22 или новее. Системные разрешения, доставку уведомлений и GPS проверьте на iPhone или в iOS Simulator.

1. Откройте карту и разрешите геолокацию и уведомления. Проверьте синий маркер и кнопку **«Моё местоположение»**.
2. В симуляторе на macOS задайте координаты командой `xcrun simctl location booted set 56.8410,60.6057`. Создайте долгим нажатием метку около `56.8389,60.6057`. На iPhone можно воспроизвести сценарий пешком возле выбранной точки.
3. Подайте точку внутри зоны командой `xcrun simctl location booted set 56.8394,60.6057` и проверьте появление одного уведомления. Сместитесь внутри зоны, затем задайте исходную точку из шага 2. Уведомление должно исчезнуть из Центра уведомлений. Вернитесь внутрь и проверьте повторное срабатывание.
4. Создайте две близкие метки и войдите в обе зоны. Дождитесь уведомления для каждой и удалите одну метку на экране деталей. Проверьте, что исчезло только уведомление удалённой метки.
5. Поочерёдно запретите доступ к местоположению, запретите уведомления и выключите службы геолокации. Проверьте сообщение об ошибке, включите нужное разрешение или службу в настройках и нажмите **«Повторить»**. При запрете уведомлений синий маркер должен продолжать обновляться.
6. Сверните приложение внутри зоны, смените координаты на точку вне зоны и снова откройте его. Уведомление должно исчезнуть после получения новых координат. Полностью завершите приложение или перезагрузите устройство при активном уведомлении и проверьте очистку при следующем запуске.

## Ошибки и ограничения

- Приложение рассчитано на **Android и iOS через Expo Go**. Веб-версия не предусмотрена.
- Карта загружает изображения местности из сети. Без интернета часть карты может оставаться пустой, уже загруженные участки иногда доступны из кеша устройства.
- Если карта не сообщает о готовности за 20 секунд, появляется сообщение с кнопкой **«Повторить»**. На Android таймер ожидает событие `onMapLoaded`, на iOS — инициализацию нативного компонента через `onMapReady`.
- `MapErrorBoundary` перехватывает ошибки отрисовки React. Он не может перехватить все сетевые ошибки карт или сбой самого нативного приложения. У библиотеки карт нет универсального события для каждой ошибки загрузки участков, поэтому таймер — простая подсказка при долгом ожидании, а не точная диагностика сети.
- Ошибки открытия галереи и получения изображения показываются сообщением. Если выбранная фотография стала недоступной, в списке появляется пояснение.
- Неверный или отсутствующий `id` маркера открывает экран **«Маркер не найден»** с возвратом к карте.
- При ошибке открытия или подготовки базы приложение показывает сообщение с кнопкой **«Повторить»**. Провайдер закрывает соединение после неудачной инициализации и при размонтировании, дождавшись операций в очереди.
- При сбое записи интерфейс сохраняет прежние данные и показывает сообщение об ошибке.
- Удаление маркера выполняется в транзакции. Локальные копии файлов удаляются после её фиксации. Если запись нового фото не удалась, приложение очищает созданную копию. При следующем открытии базы оно повторяет очистку файлов, на которые больше нет ссылок.
- В режиме разработки операции и причины сбоев выводятся в консоль с префиксом `[SQLite]`.
- GPS и проверка расстояния работают в активном приложении. Перемещение в фоне учитывается после возврата и получения свежих координат.
- Частоту обновления на iOS определяет система. Погрешность GPS около границы 100 м может привести к выходу из зоны и повторному входу. Появление баннеров зависит от настроек уведомлений и режима фокусирования iOS.
